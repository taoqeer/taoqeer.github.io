How I made a tax processing script 240× faster

Draft — publishing soon

When I joined EY, one of the first things I inherited was a Python script that processed taxation data for enterprise clients. It worked. Mostly. The problem: it took over 2 hours to run. Every. Single. Time.

By the time I was done, it ran in under 30 seconds. That's a 240× improvement. This post is about how I got there — not just the technical fixes, but how I thought about the problem.

Step 1: Don't guess. Profile first.

The worst thing you can do when optimizing is start changing things without data. I started with Python's built-in cProfile to get a real picture of where time was actually going. 

import cProfile
import pstats

profiler = cProfile.Profile()
profiler.enable()

# ... run the script logic ...

profiler.disable()
stats = pstats.Stats(profiler)
stats.sort_stats('cumulative')
stats.print_stats(20)

The output was eye-opening. ~70% of runtime was in file I/O — specifically, the script was reading the same reference data files hundreds of times inside a loop.

Step 2: The obvious fix — cache the reference data

The script had a pattern like this: 

# Before — reading from disk thousands of times
for record in records:
    rates = read_tax_rates_from_file()   # disk read every iteration
    result = calculate(record, rates)

The fix was embarrassingly simple: 

# After — read once, reuse
rates = read_tax_rates_from_file()       # read once
for record in records:
    result = calculate(record, rates)

This alone got us from 2 hours to about 18 minutes. Good, but not good enough.

Step 3: Vectorize with Pandas instead of looping

The calculation logic was doing row-by-row iteration with a Python for loop over a DataFrame. This is one of the most common Pandas anti-patterns. 

# Before — slow Python loop
results = []
for idx, row in df.iterrows():
    results.append(compute_tax(row['amount'], row['category']))

# After — vectorized operation
df['tax'] = df.apply(lambda row: compute_tax(row['amount'], row['category']), axis=1)
# Or even better with NumPy:
df['tax'] = np.where(df['category'] == 'A', df['amount'] * 0.18, df['amount'] * 0.12)

The final result

After profiling, caching reference data, vectorizing operations, and eliminating redundant file reads — the script went from 2+ hours to under 30 seconds. A 240× improvement.

The biggest lesson: profile before you optimize. I could have spent a week rewriting things that didn't matter. The profiler told me exactly where the problem was in 5 minutes.
